[1] كيف تسير وتعمل منظومة الصلاحيات في Backend؟ (Architecture & Workflow)
════════════════════════════════════════════════════════════════════════════════
يعتمد النظام على تكامل وسيط الأمان المخصص (CheckPermissionMiddleware)
مع حزمة (Spatie Laravel Permission) وحارس التوثيق (auth:sanctum).

مراحل فحص الصلاحية عند كل طلب (Request Lifecycle):
--------------------------------------------------
1. المصادقة والتوثيق (Authentication):
   - يتم التحقق من صحة التوكن المرسل عبر الهيدر (Authorization: Bearer)
     باستخدام حارس Sanctum (auth:sanctum).

2. استثناء وتجاوز المشرف العام (Super Admin Bypass):
   - في حال كان حساب المستخدم يملك رتبة "super_admin"، يتم تجاوز فحص
     الصلاحيات وتمرير الطلب فوراً إلى الكنترولر (Super Access).

3. المطابقة الديناميكية التلقائية للمسارات (Dynamic Route Resolution):
   - يمر الطلب عبر وسيط (CheckPermissionMiddleware).
   - يقوم الميدلوير بقراءة طريقة الطلب (GET / POST / PUT / DELETE / PATCH)
     ومسار الرابط (URI)، ومطابقته تلقائياً مع مصفوفة الصلاحيات المدمجة
     (مع دعم المعاملات المتغيرة مثل {id} و {club} و {member}).
   - مثال: الطلب (POST:v1/members/register) يُترجم آلياً إلى صلاحية (member.create).

4. التحقق من صلاحيات المستخدم (Spatie Check):
   - يفحص النظام قاعدة البيانات والذاكرة المؤقتة للتحقق من امتلاك المستخدم
     لهذه الصلاحية عبر ($user->can($permission)) سواء كانت ممنوحة له مباشرة
     أو موروثة من أدواره/رتبه.

5. الاستجابة أو المنع (403 Forbidden Response):
   - إذا كان المستخدم يملك الصلاحية: يتم تمرير الطلب بنجاح (200 OK).
   - إذا لم يكن يملكها: يُرجع الـ Backend خطأ منع (403 Forbidden) برسالة JSON
     توضح اسم الصلاحية المفقودة بدقة:
     {
         "status": "error",
         "message": "عذراً، ليس لديك الصلاحية الكافية لإتمام هذا الإجراء.",
         "permission": "member.create"
     }

[2] مصفوفة الأدوار والرتب المعتمدة في النظام (Roles Matrix)
════════════════════════════════════════════════════════════════════════════════
• super_admin       : مالك المنظومة — تجاوز كامل لجميع فحوصات الصلاحيات.
• admin             : مدير النظام — يمتلك كافة صلاحيات النظام (272 صلاحية).
• accountant        : المحاسب المالي — دليل الحسابات، القيود، الصناديق، التسويات، الرواتب، وسندات الصرف.
• reception         : موظف الاستقبال — تسجيل الأعضاء، حضور وانصراف QR، خصم الحصص، وتأجير الخزائن.
• coach             : المدرب — استعراض الحصص والجداول التدريبية واللاعبين التابعين له.
• player            : المشترك / اللاعب — الخدمة الذاتية، الاشتراكات، الفواتير، وسجل الحضور.
• management_admin  : الإدارة التشغيلية — إدارة الفروع، الشفتات، والإجازات الرسمية.
